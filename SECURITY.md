# Security and private-data reports

Do not place credentials, private source material, employer or customer information, personal data, or undisclosed vulnerability details in a public issue.

For a sensitive report, use GitHub's private vulnerability-reporting option on the repository's **Security** tab when it is available. If that option is unavailable, contact the repository owner through their GitHub profile with only enough non-sensitive information to establish a private communication path.

Ordinary content inaccuracies, broken public links, accessibility defects, and exam-objective changes are not security vulnerabilities and should use the structured public issue forms.
