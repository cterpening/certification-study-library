## Scope and technical corrections

The previous transition paragraph incorrectly grouped DHCP with topics leaving the named future scope. DHCP moves to domain 1 as troubleshooting of client, server and relay. SNMP and syslog remain in domain 5. The guide preserves current v1.1 learning and separates future configuration/troubleshooting, OSPFv3, DNS records, secure file transfer, Layer 2 controls and AI/Ansible tasks. The future OSPF adjacency objective explicitly excludes authentication.

[Cisco’s route-selection explanation](https://www.cisco.com/c/en/us/support/docs/ip/border-gateway-protocol-bgp/15986-admin-distance.html) supports a distinction between candidate selection/route installation and later packet forwarding. The revised guide explains why a more-specific installed prefix wins despite a higher AD and why unrelated protocol metrics are not common units. Floating-static behavior depends on route eligibility and withdrawal, not merely an application outage. The local workbook exercises those distinctions without claiming next-hop probes or real convergence.

LACP member loss is now conditioned on minimum-links requirements; reduced capacity is not guaranteed when the whole bundle becomes ineligible. OSPF teaching separates normal broadcast DROTHER 2-WAY relationships from persistent database-exchange faults; MTU mismatch is one possible cause, not a reason to blindly ignore MTU. STP role/state teaching now includes learning and reconciles generic RSTP terminology with platform blocking/disabled labels, without transplanting NX-OS configuration into IOS.

ACL material adds noncontiguous wildcard matching, rule shadowing, independent return-direction policy and ACK/RST matching without a connection-state database. DAI teaching distinguishes DHCP-learned bindings, static-host ARP ACLs and trusted interfaces that bypass checks. API material adds pagination and error handling without suggesting every Cisco API has the Secure Endpoint contract. Worked subnet and modified EUI-64 examples were separately checked. Technical documents were read in selected sections, with precise boundaries in the source notes; this was not a comprehensive review of every linked configuration guide or RFC.

## Executed local evidence and remaining labs

The exact public Python workbook passed **48 checks**. It builds six synthetic installed prefixes, retains two equal-cost OSPF candidates, changes to a floating static after supplied eligibility changes, restores the original candidates and preserves a more-specific host route. It checks IPv4/IPv6 separation, no-route cases, unusable candidates, AD 255, invalid/tied model inputs and input-order independence. ACL cases test permitted/denied/unmatched traffic, wildcard boundaries, reversed ordering, a denied reply, ACK/RST behavior and a JSON round trip.

The code is an original bounded teaching model. Its route eligibility is provided, not measured. It supports one process and comparable metric class per source and rejects unsupported AD combinations. It implements neither real OSPF nor recursive next-hop resolution, tracking, convergence, policy routing or ECMP hashing. ACLs use selected parsed IPv4 fields and trusted fixtures, not IOS syntax or packet parsing, fragmentation, NAT, interface application, comprehensive validation or session tracking. Some checks are structural/input-rejection assertions. Four separate checks validate subnet/range/host-count and EUI-64 arithmetic.

There was no device, simulator, wireless controller, authenticated API, credential, socket, provider lab or live enforcement exercise. The guide now contains **48 individually answered original prompts**, three retained integrated scenarios and eight concrete proposed labs with controlled faults, expected observations and restoration. These labs and independent human review remain pending.
