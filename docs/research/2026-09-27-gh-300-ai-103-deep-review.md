## GH-300 decisions and changes

The guide now distinguishes an enforced feature policy from an overridable review-effort default. GitHub's [September 23 release](https://github.blog/changelog/2026-09-23-copilot-code-review-more-ways-to-request-and-configure-reviews/) supports that distinction. Requesting an automatic review, setting review effort, and satisfying a merge rule are separate actions.

The organization-instruction section adds the supported JetBrains plugin/session boundary from the [September 22 release](https://github.blog/changelog/2026-09-22-new-features-and-improvements-in-copilot-for-jetbrains/). The guide also explains the forthcoming [October 22 default-availability transition](https://github.blog/changelog/2026-09-24-default-enablement-of-copilot-features-for-copilot-business-and-enterprise/) while preserving explicit feature choices, delegated organization settings, and preview exclusions. An announcement is not evidence that a future rollout has completed.

The Terraform workflow example previously used path filtering even though learners were instructed to require its result. A documentation-only pull request could therefore remain pending. The example now runs for all pull requests, includes the merge-queue event, and explains project-directory and version assumptions, following [required-check troubleshooting](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks). The workflow was reviewed as documentation; it was not executed against a Terraform project.

Four worked examples connect acceptance criteria, context selection, customization mechanisms, and productivity measurement. Two new labs exercise independent boundary tests and policy/merge controls. Five additional scenarios have answer explanations. The productivity example explicitly avoids treating sums of stage medians as measured end-to-end medians, and the [new review-stage metrics](https://github.blog/changelog/2026-09-25-usage-metrics-api-adds-pull-request-review-stages/) are scoped to their qualifying human-review population.

The September 24 training event is now labeled past. The guide points learners to current credential and recertification information without converting a credential extension into a blueprint change.

## AI-103 decisions and changes

The catalog prerequisite now matches the official Python requirement. The guide adds an identity matrix and a migration failure drill: copying an agent definition does not transfer downstream role assignments. The [Foundry migration guidance](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/migrate-agent-applications) supports the newer identity/endpoint explanation while continuing to describe legacy Agent Applications as supported during transition. No retirement deadline is invented.

Six worked examples follow a fictional maintenance assistant through identity, retrieval, tools, vision, speech, and document extraction. The original local Python example computes explicitly defined set-based retrieval precision and recall. It distinguishes relevance from authorization, ranking, provenance linkage, and claim-level groundedness. Empty-label questions receive a separate abstention treatment.

The tool example shows why HTTP success can coexist with acting on the wrong asset. It maps failure questions to [current agent evaluators](https://learn.microsoft.com/en-us/azure/foundry/concepts/evaluation-evaluators/agent-evaluators), while keeping approval and authorization in application controls. The [current evaluation workflow](https://learn.microsoft.com/en-us/azure/foundry/observability/how-to/evaluate-agent) informs version pinning, trajectory inputs, bounded polling, and accounting for missing or errored cases.

The SDK section adds an implementation checklist for compatible package versions, endpoint contracts, token audiences, runtime identities, and renamed RBAC roles. A new integrated lab can be completed with synthetic offline fixtures before optional cloud work. All six previous knowledge checks now have answer checkpoints, and six additional answered checks cover the new examples.

The release sweep included the [July/August Foundry roundup](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-july-august-2026/) published September 9, current SDK/agent documentation, and Content Understanding release notes. It did not treat every announcement as another exam objective or add redundant guide links.
