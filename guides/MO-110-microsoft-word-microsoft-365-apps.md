## How to use this guide

MO-110 rewards accurate document production under time pressure. Build every practice document from a short requirement, save a clean result, then inspect formatting marks, navigation, accessibility, print layout, and sharing state. Learn more than one route to common commands, but choose the fastest route you can verify. Practice in the desktop Microsoft 365 Apps environment used by your testing center; browser, Mac, and newer release-channel features can differ. The credential page currently lists 16 languages and no dedicated Learn training collection. The time estimates below are this guide’s study suggestions, not provider runtimes or exam prerequisites.

## 1. Manage documents

Know Save As, export to PDF, print settings, document properties, page setup, views, zoom, Navigation pane, and find/replace. Inspect compatibility and accessibility before delivery. Restrict editing only after confirming what collaborators still need to do, and never treat a password as a substitute for an authorized storage boundary.

Headers, footers, page numbers, margins, orientation, and page size affect the whole document unless sections divide the layout. A page break starts a page; a section break can change headers, numbering, columns, margins, or orientation. Reveal formatting marks when the result seems inexplicable.

> **Related item:** A document can look correct on screen and still fail in PDF or print. Always check page boundaries, repeated headings, image movement, hidden markup, and metadata in the delivered format.

For precise navigation, use Find for matching text, the Navigation pane for styled headings, and Go To for a page, section or object. A bookmark names a destination; an internal hyperlink takes the reader there. Test the destination after moving content. Show hidden text and paragraph marks when diagnosing layout; their visibility is a display choice, not removal.

A style set coordinates the document's styles; individual style changes affect paragraphs using that style. Page color, borders and watermarks are document-background choices: inspect their appearance in the required output. Save a separate copy before converting formats, and use the Compatibility Checker when a recipient needs an older format.

[Document Inspector](https://support.microsoft.com/en-us/office/collab-files/remove-hidden-data-and-personal-information-by-inspecting-documents-presentations-or-workbooks) should run on a delivery copy. Select removal categories deliberately: removing headers can also remove required page numbers. It does not find every visually concealed item, including white-on-white text or an object hidden behind another object. Inspect the visible output too; a clean report is not proof of confidentiality.

## 2. Text, paragraphs, and sections

Use styles for repeated structure. Direct formatting changes one selection; modifying a style changes every paragraph using it. Clear accidental formatting before rebuilding a consistent hierarchy. Know character formatting, paragraph alignment and spacing, indentation, tabs, columns, drop caps, themes, and format copying.

Use Keep with next for headings, Keep lines together for indivisible paragraphs, and widow/orphan control for readable pagination. Apply columns or orientation to the intended section, not accidentally to the rest of the document. Replace text, formatting, and special characters carefully; verify scope before Replace All.

When inserting a special character, use the symbol dialog rather than a look-alike font glyph. Text effects such as outline and shadow change appearance; a character style makes repeated emphasis consistent. Format Painter copies formatting, not the underlying words. After clearing formatting, reapply the intended style and check both character and paragraph settings.

Columns flow within a section. A column break moves subsequent text to the next column; a page break moves it to a new page without creating independent section settings. Place section breaks before and after a landscape insert when the following pages must return to portrait. Check each section's header/footer linkage separately before editing its contents.

## 3. Tables and lists

Create tables from scratch or delimited text; insert/delete rows and columns; merge/split cells; set alignment, margins, height, width, AutoFit, borders, shading, and repeating header rows. Sorting a table depends on the correct header and data type. Converting between text and a table depends on a delimiter that does not also occur inside the data.

For lists, distinguish bullets, numbering, and multilevel lists. Continue or restart numbering intentionally. Link heading levels to a multilevel list when the document needs durable outline numbering; manual numbers become wrong as content moves.

Splitting a table creates a separate table; splitting a cell subdivides a cell inside it. Cell margins control the inset between content and its border, while cell spacing separates cells. After merging cells, recheck row structure before sorting. Custom list symbols and number formats should use a consistent definition; changing a list level is different from adding spaces before its text.

For [repeating table headers](https://support.microsoft.com/en-us/word/repeat-table-header-on-subsequent-pages), select rows beginning with the table's first row. Verify in Print Layout or print output. Repetition works across automatic page breaks; a manually inserted page break inside the table prevents the expected repetition. Edit the original header rather than trying to edit its repeated display.

## 4. References

Create and update tables of contents from heading styles. Insert footnotes/endnotes, hyperlinks, bookmarks, and cross-references, then test navigation. References are fields: after headings, captions, or pagination change, update them and inspect the result.

Footnotes appear near their referenced page; endnotes collect at the end of a section or document. Set location, number format and restart behavior in the note dialog, and check the reference mark and note together after edits.

A contents table can be customized for heading depth, page-number alignment and leader style. If headings were renamed or added, [update the entire table](https://support.microsoft.com/en-us/word/update-a-table-of-contents); updating page numbers alone leaves old heading text. A manually typed contents list cannot be regenerated from heading structure. Cross-references are useful additional practice alongside the PDF's note and contents tasks.

## 5. Graphic elements

Insert pictures, shapes, icons, text boxes, SmartArt, screenshots, and symbols; resize proportionally, crop, align, distribute, group, layer, rotate, and apply a restrained style. Understand In Line with Text versus floating wrap modes and anchors. Add meaningful alt text; mark an image decorative only when it conveys no information.

Practice each graphic type rather than substituting a picture for every task. Use a screenshot for a whole window and a screen clipping for a selected area. Enter and revise text inside a shape or text box, and use the SmartArt text pane to edit nodes without treating the diagram as one flat image. Artistic effects alter a picture's rendering; picture styles add coordinated framing/effects. For background removal, inspect the proposed foreground and refine the areas to keep or remove before accepting; cropping merely hides outer portions.

For a [3D model](https://support.microsoft.com/en-us/office/graphics-visuals/get-creative-with-3d-models), insert a local model, select a useful view, then adjust size and placement. The 3D control changes the model's viewpoint; rotating its frame is a different operation. Keep the important feature visible and provide an equivalent text explanation. Check the final PDF because an interactive model's behavior should not be assumed to survive export.

## 6. Collaboration

Add, reply to, resolve, and delete comments. Track changes records insertions, deletions, moves, and formatting; showing No Markup does not accept changes. Review by author or change type, then accept/reject deliberately. Compare identifies differences between versions; combine can consolidate revisions. Before sharing, inspect permissions, comments, tracked changes, document properties, and hidden content.

[Track Changes](https://support.microsoft.com/en-us/word/training/track-changes-in-word) has separate controls for recording, display and acceptance. Turning it off stops tracking future edits; it leaves existing revisions. In Windows, use Review > Tracking > Track Changes > Lock Tracking when the exercise requires a password-controlled review. Unlock before accepting/rejecting revisions. Resolving a comment marks the discussion dealt with; deleting removes it. Neither action substitutes for reviewing the associated text change.

## Worked examples

1. **A landscape appendix affects the remaining pages.** A six-page portrait proposal needs a wide table in the middle. Create a section for the table and another boundary before the following text; apply landscape only to the middle section. Inspect the three regions and their header/footer linkage. A page break alone does not isolate orientation.
2. **A contents page preserves an old title.** Rename “Delivery” to “Implementation” and add a heading beneath it. Updating only page numbers cannot fix the text or add the entry. Update the entire automatic table and verify the new name, level and destination.
3. **A repeated header disappears.** A long inventory table repeats correctly until someone forces a page break within it. Remove that manual break and let the table paginate; confirm the selected repeat rows include the first row. Compare Print Layout and exported output.
4. **A clean-looking review still contains revisions.** Four edits are present, two approved and two rejected. No Markup hides the evidence. Unlock tracking if needed, accept the two approved edits and reject the other two, then inspect all reviewers and save a separate final copy. Keep the review copy for the revision history.
5. **Sanitizing a file removes required material.** The delivery copy contains an author name, internal comments and a page-number footer. Remove only the unwanted categories, retain the required footer, and reinspect. Also look for visually hidden content that the inspector does not detect. Verify the PDF separately.

## Integrated practice scenarios

1. **Policy memo:** Apply heading styles, numbered procedures, a landscape table section, cross-references, page numbering, alt text, and a clean PDF.
2. **Client proposal:** Import supplied text, build branded styles, place images with stable wrapping, create a contents page, and remove hidden review data before delivery.
3. **Team procedure:** Track two revision rounds, reconcile comments, compare with a baseline, accept only approved changes, and preserve a review copy.

### Additional answer checkpoints

21. **What distinguishes a column break from a section break?** The first advances within columns; the second creates a boundary for independent layout settings.
22. **Can a manual page break fix missing repeated table headers?** It can cause the problem; use automatic table pagination and a repeat selection starting at the first row.
23. **What refresh is needed after renaming a heading?** Update the entire automatic contents table.
24. **Does stopping Track Changes accept earlier edits?** No; acceptance/rejection is a separate action.
25. **Why unlock tracking before final review?** Locked tracking prevents the accept/reject operation.
26. **Is a resolved comment necessarily deleted?** No; the discussion's state and removal are different operations.
27. **Does cropping remove an image background around the subject?** No; it hides material outside the crop boundary.
28. **What does a model's 3D control change?** Its viewpoint, which differs from rotating the flat frame.
29. **Why inspect a copy?** Removal may not be reversible and can discard required content.
30. **Does a clean inspector report prove no concealed content remains?** No; inspect visual hiding and the exported result too.
31. **Are cloud location links guaranteed in the exam?** No; the article describes specified application builds, not the exam environment.
32. **Does no exam retirement notice mean a credential lasts forever?** No; current MOS expiration policy and exam availability are separate.
