## How to use this guide

Build a presentation for a defined audience and delivery channel. Work on copies, use layouts and masters for consistency, and check the saved output in Slide Show and its actual export format. Desktop practice is needed for the full scope. The labs below are proposed exercises; no PowerPoint application or screen-reader session was executed for this review.

> **About related items:** Captions, export checks and other supporting practices deepen understanding. They do not add separate requirements to the published exam outline.

## 1. Presentations, masters and delivery

Change the Slide Master's theme/background and shared content, then create and modify layouts with appropriate placeholders. Apply a layout to a test slide and inspect inheritance. Reset a slide when placeholder positions/formatting drift; independently drawn text boxes do not become placeholders just because they look similar. Keep slide-specific content on its slide.

Treat **Handout Master** and **Notes Master** as separate outputs: adjust shared branding and placeholders, then preview both. Change slide size early and inspect cropping/fit when converting an existing deck. Use Normal to edit, Slide Sorter to inspect sequence, Notes Page to inspect printed notes, and master views for shared design. Update built-in properties such as Title and Author to suit the deliverable.

Print slides, notes pages and handouts deliberately. Confirm selected slide ranges, slides per handout page, orientation, color/grayscale and whether hidden slides are included. Notes pages combine a slide image with speaker notes; a six-slide handout is a different output. A correct on-screen footer does not prove the printed notes header is right.

Create a **custom slide show** for a selected audience, order its slides, and test that named show. Configure full-screen speaker delivery or the required kiosk/browser options; rehearsed timings, narration and manually advanced delivery are distinct choices. Rehearse, accept or discard timings deliberately, and configure microphone/camera/ink recording options before recording a show. In Presenter View, verify the audience sees the slide while the presenter sees notes, navigation and timing controls. Test the actual display arrangement.

Set editing controls according to the requirement. [Mark as Final](https://support.microsoft.com/en-us/office/collab-files/help-prevent-changes-to-a-final-version-of-a-file) discourages changes but recipients can remove it; it is not access security. If a password is required, distinguish opening the file from modifying it and verify the chosen protection on a disposable copy. Apply organization permissions only in an authorized environment.

Manage comments and replies, resolve addressed discussions and inspect what remains before distribution. Run Document Inspector on a copy, check accessibility/compatibility, and review hidden slides, notes, metadata and embedded content. Preserve the editable master before removing information or compressing content. Save in the required format: an editable deck, a show that opens into presentation mode, a static PDF, and a video have different behavior. Check the exported artifact rather than assuming animation, interactive links and media survive every format.

## 2. Slides and navigation

Import a structured Word outline using Heading 1 for slide titles and Heading 2 for bullet content; save and close Word before importing. Unstructured paragraphs can produce an unintended slide per paragraph. Normal-style body text is not a substitute for outline headings. Desktop Windows and Mac have different accepted-file details, and the web app does not import outlines. See [Microsoft's outline workflow](https://support.microsoft.com/en-US/PowerPoint/training/create-a-powerpoint-presentation-from-an-outline).

Insert slides from another presentation and deliberately choose source or destination formatting. Create or duplicate a slide, choose its layout, and confirm the imported theme/master behavior. Hide/unhide slides without confusing that with deletion or access control. Modify individual backgrounds when the story needs an exception. Create, rename and reorder sections; move an entire section and confirm its slide membership.

The PDF uses broad header/footer wording. In the desktop **Header & Footer** dialog, the Slide tab supplies date/time, footer and slide-number controls; **Notes and Handouts** has separate header/page controls. A top-of-slide banner can be designed on a slide/layout; it is not the notes-page header field. Check both [slide numbering](https://support.microsoft.com/en-US/PowerPoint/training/add-slide-numbers-page-numbers-or-the-date-and-time) and [notes headers/footers](https://support.microsoft.com/en-us/powerpoint/edit-page-numbering-footers-and-headers-for-notes-pages-in-powerpoint), including title-slide exclusions and whether a layout exposes the placeholders.

Use **Summary Zoom** for a navigation overview, **Section Zoom** to visit a section and **Slide Zoom** to visit a particular slide. Creating a summary can create sections around the selected starting slides. Editing the summary's included sections is different from deleting sections or slides. Summary/Section Zoom normally return to the zoom slide after the visited section; Slide Zoom normally continues forward. Inspect **Return to Zoom** instead of assuming all three behave alike. See the [Zoom workflow and version table](https://support.microsoft.com/en-us/powerpoint/use-zoom-for-powerpoint-to-bring-your-presentation-to-life); creation/playback support differs by platform. Test navigation in Slide Show.

## 3. Text, shapes, images and reading order

Format text styles, size, emphasis, paragraph spacing, columns, bullets and numbering to express hierarchy. Use meaningful hyperlink text, check its destination and test both external links and links within the deck. A visible label is not proof that the target is correct. Section/Slide Zoom links are covered in section 2.

Insert pictures, screenshots and screen clippings; choose a crop and resize with the aspect ratio preserved when distortion is not intended. Compare picture styles/effects without hiding important information. Distinguish scaling the image from changing the visible crop. Insert shapes, icons and other graphics, add text, draw with digital ink, and adjust size, fill, outline and built-in styles.

Show guides/gridlines and use Align/Distribute for precise placement. Choose alignment to the slide or selected objects deliberately. Arrange front/back order and group objects that should move together. Use the [Selection pane](https://support.microsoft.com/en-us/powerpoint/use-the-selection-pane-to-manage-objects-in-documents) to name, select, hide and reorder objects; its list represents visual stacking order, with front objects at the top.

Use the numbered sequence in the [Reading Order pane](https://support.microsoft.com/en-us/powerpoint/make-slides-easier-to-read-by-using-the-reading-order-pane) to inspect the assistive reading sequence. Do not infer that sequence from the visual layout alone. Add meaningful alt text to informative graphics and mark only genuinely decorative objects as decorative. Review generated descriptions. Reordering can affect overlapping objects; grouping already animated objects can remove their animations. Recheck appearance and motion after an accessibility edit.

## 4. Tables, charts, diagrams, 3D models and media

Create a table, insert/delete rows and columns, and apply a built-in style while retaining readable headers and values. Use charts for comparisons/trends: enter or edit their underlying data, choose a suitable chart type, and configure series, axes, titles, legend and data labels. Reconcile chart values with the source; formatting cannot repair a wrong series or unit.

Insert SmartArt for a list, process or hierarchy; add/edit nodes and promote/demote their levels. Convert between a list and SmartArt and check that the original ordering/hierarchy survives. Diagram structure conveys meaning beyond its text. For example, a manager with two direct reports is not the same relationship as a three-step process.

**Useful recent article:** Shireen Salma's [SmartArt accessibility update](https://techcommunity.microsoft.com/blog/microsoft365insiderblog/smartart-is-becoming-more-accessible-in-powerpoint/4507653), August 24, 2026, describes programmatically generated descriptions in the accessibility tree, updated as diagram structure/content changes. It lists Windows Microsoft 365 PowerPoint **2607, build 20326.20158 or later**, with rollout caveats. This is not a general promise that every build needs no accessibility review. Verify the actual screen-reader output, including relationships, and maintain useful descriptions where needed. The announcement does not change the exam outline or guarantee the exam environment's build.

Insert a 3D model and change its viewpoint, size and appearance. Distinguish rotating the model within its frame from moving/resizing the frame. Apply a supported [3D animation effect](https://support.microsoft.com/en-us/powerpoint/3d-animation-effects-in-powerpoint), such as Turntable, and adjust direction/axis/intensity where available. Microsoft documents web playback and creation restrictions separately; use a suitable desktop build for creation practice.

Insert audio/video and configure start, volume, trim, loop, rewind, poster frame and across-slide options where supported. Embedded and linked media have different dependencies; test playback on the delivery device after moving/copying the presentation. Do not assume embedding alone guarantees codec or platform compatibility.

Practice [screen recording](https://support.microsoft.com/en-us/powerpoint/training/record-your-screen-in-powerpoint): choose a small area, check the audio/pointer toggles, record a harmless local task, stop, trim and replay the inserted video. This captures a screen region; recording an entire presentation's narration and timings is a separate workflow. Use non-sensitive demonstration content.

**Supporting media practice:** Add and verify captions through the [current caption workflow](https://support.microsoft.com/en-us/powerpoint/add-closed-captions-or-subtitles-to-media-in-powerpoint). WebVTT and, on documented newer builds, UTF-8 SRT files are supported; platform/version details matter. Use [Audio and Subtitles controls](https://support.microsoft.com/en-us/powerpoint/accessibility-features-in-video-and-audio-playback-on-powerpoint) in Slide Show to select the intended track. Captions for recorded media and live subtitles for your speech solve different problems.

[Compress Media](https://support.microsoft.com/en-us/powerpoint/compress-your-media-files) is a Windows feature, not a Mac/web feature in the cited reference. Microsoft warns that compression loses embedded subtitles and alternate audio tracks. Keep the original and retest accessibility tracks, playback and quality in the compressed/exported deliverable. A smaller file is not evidence of an equivalent accessible presentation.

## 5. Transitions and animations

Apply basic and 3D slide transitions, configure their effect options, duration and advance timing, and inspect whether the setting applies to one slide or all slides. A transition moves between slides; a 3D transition is not the same operation as animating a 3D model.

Animate text and graphics with a purposeful sequence. In the Animation pane, select the correct effect, set its options, reorder it, and configure a motion path. Inspect path start/end positions and the final object position. Use **Add Animation** when adding another effect to an already animated object rather than unintentionally replacing its current effect.

[Start, Duration and Delay](https://support.microsoft.com/en-us/powerpoint/set-the-start-time-and-speed-of-an-animation-effect) answer different questions: what triggers the effect, how long it runs, and how long it waits after that trigger. On Click waits for a click; With Previous shares the preceding effect's start; After Previous waits for its end. An additional delay still applies. Preview the full show and test any object triggers, rather than relying on editing-view numbers.

## Worked examples

These are small, reproducible practice specifications. Local Python checks verify expected counts, geometry, arithmetic and simplified timing; they do not execute PowerPoint, its renderer or assistive technology.

### 1. Predict the imported outline

Create six Word paragraphs: Heading 1 **Situation**, Heading 2 **Demand**, Heading 2 **Capacity**, Heading 1 **Decision**, Heading 2 **Option A**, Heading 2 **Option B**. In a fresh deck, remove any starter slide before importing the saved/closed outline. Expect **two imported slides**, each with a title and **two bullet items**. If six slides appear, inspect the source heading structure before deleting slides manually.

### 2. Design a return route

Use an agenda slide and a three-slide section titled **Evidence**. Insert a Section Zoom on the agenda, visit all three section slides and expect a return to the agenda with Return to Zoom enabled. Add a Slide Zoom to the middle evidence slide. Its default forward behavior differs: enable Return to Zoom if the desired route is **Agenda → Evidence detail → Agenda**. Check both routes again after moving the section; do not describe slide numbers as permanent identifiers.

### 3. Preserve image proportions

A 1920×1080 image has a 16:9 ratio. At **8 inches wide**, proportionate height is **4.5 inches**. Forcing it to 8×6 stretches it vertically. If the design needs an 8×6 frame, compare a deliberate crop with distortion and verify that the important subject remains visible. Alt text should explain the visible meaning, not dimensions alone.

### 4. Predict an animation sequence

Use three simple shapes, one effect each, no repeats or other effects. Relative to the first click at time zero: A is On Click, duration **1.0s**, no delay; B is With Previous, delay **0.5s**, duration **2.0s**; C is After Previous, delay **0.25s**, duration **0.75s**. Expected intervals are **A: 0–1.0s**, **B: 0.5–2.5s**, **C: 2.75–3.5s**. C's delay starts after B ends. This is a simplified timing model to test in Slide Show, not a measured renderer result.

### 5. Match chart meaning to the data

Enter January **120** and February **180** as units sold. The total is **300**, the increase is **60**, and growth relative to January is **50%**. Create a two-column chart with a zero baseline and labeled units. A useful description is “Units sold rose from 120 in January to 180 in February, an increase of 50%.” Do not describe it as 60% or change units to currency. Recheck both source cells and chart after an edit.

## Original readiness checks and answers

1. **Theme versus layout?** Coordinated design settings versus placeholder structure/position.
2. **Why use a master?** To maintain shared design and content across related layouts/slides.
3. **Does Reset turn a text box into a placeholder?** No; it restores layout-controlled placeholders.
4. **Handout Master versus Notes Master?** Shared handout pages versus slide-and-speaker-note pages.
5. **Why preview after changing slide size?** Content can be cropped, scaled or repositioned.
6. **Does a hidden slide cease to exist?** No; it remains in the file and can be included in other outputs.
7. **Heading 1 versus Heading 2 on outline import?** Slide title versus bullet content.
8. **Why close the Word source?** The documented import workflow requires the saved document closed.
9. **When preserve source formatting?** When the imported slides must retain their original design.
10. **Is a section a custom show?** No; it organizes slides, while a custom show selects/orders a delivery subset.
11. **Summary Zoom versus Slide Zoom?** Section overview navigation versus a link to a particular slide.
12. **Why inspect Return to Zoom?** Defaults differ and determine whether navigation returns or continues.
13. **Is the notes header the slide banner?** No; they are separate content/output controls.
14. **Does Mark as Final prevent an authorized recipient editing forever?** No; the recipient can remove the status.
15. **Why inspect a copy?** Removing metadata or hidden content can discard information needed in the original.
16. **What does Presenter View need tested?** The display arrangement and what presenter and audience each see.
17. **Crop versus resize?** Change the visible region versus the object's dimensions.
18. **Proportional height of a 16:9 image at width 8?** 4.5 in the same unit.
19. **What does the top of the Selection pane represent?** The front of the visual stacking order.
20. **Where should reading sequence be checked?** The numbered Reading Order pane and actual assistive output.
21. **Does decorative mean unimportant-looking?** No; only objects carrying no needed information should be skipped.
22. **What can grouping animated objects change?** Existing animations may be lost; recheck them.
23. **Does automatic SmartArt description prove accessibility?** No; verify relationships and behavior on the actual build.
24. **Why edit chart source values before formatting?** Appearance cannot fix incorrect data or units.
25. **120 to 180 is what percentage growth?** 50%, using 120 as the baseline.
26. **3D model rotation versus slide transition?** Changing a model's view/motion versus moving between slides.
27. **Screen recording versus show recording?** Capture a screen region versus presentation narration/timing and related options.
28. **Does compressed media preserve all accessibility tracks?** No; Microsoft documents losses, so retain and verify originals/output.
29. **Duration versus delay?** How long an effect runs versus how long it waits after its trigger.
30. **After Previous delay begins when?** When the preceding effect ends.
31. **Why use Add Animation?** To add another effect without unintentionally replacing the selected one.
32. **Does a good editing view prove delivery readiness?** No; test Slide Show, navigation, media and each final output.
